- 首页：搜索框 + Banner 轮播 + 快捷入口（金刚区）+ 商品瀑布流（卡片式），底部导航四个入口（首页/消息/购物车/我的）

## 3. 系统范围与角色

| 角色 | 说明 | 是否必做 |
|---|---|---|
| 买家（C 端用户） | 注册登录、逛商品、加购、下单支付、管订单、评价 | 必做 |
| 商家/管理员 | 商品/分类/订单/用户管理 | 选做（最小化） |
| 系统 | 模拟支付、本地通知、数据初始化 | 必做 |

**范围边界（毕设标准做法）**

| 能力 | 决策 | 理由 |
|---|---|---|
| 支付 | 模拟支付（前端收银台 + 后端订单状态流转） | 真实支付需企业资质 |
| 物流 | 模拟物流轨迹（静态节点） | 无真实物流接口 |
| 消息推送 | 站内消息 + 本地通知（NotificationKit） | 免推送服务端资质 |
| 管理端 | 轻量 Web 页（可复用你的 Vue3）或 SQL 直接初始化数据 | 控制工作量 |
| 设备 | 手机必做；折叠屏/平板断点适配应做；服务卡片/跨设备流转加分 | 一多适配是鸿蒙特色，答辩加分 |

## 4. 功能需求

### 4.1 功能结构

- 买家端：启动引导 → 登录注册 →（首页 / 分类 / 搜索 / 商品详情 / 购物车 / 确认订单 / 支付 / 订单）→ 个人中心 →（地址 / 收藏 / 足迹 / 评价 / 消息 / 设置）
- 管理端（选做）：商品管理、订单管理、用户管理、数据统计
- 鸿蒙特色（P2）：服务卡片、跨设备流转、深浅色/中英文

### 4.2 功能清单

优先级：**P0 必须** / P1 重要 / P2 加分

| 模块 | 功能点 | 优先级 |
|---|---|---|
| 启动引导 | 闪屏页、引导页（3 页轮播）、登录态检查 | P1 |
| 登录注册 | 账号密码登录、注册、短信验证码（mock）、JWT token、自动登录 | P0 |
| 首页 | 搜索框、分类金刚区、Banner 轮播（Swiper）、商品瀑布流（WaterFlow）、下拉刷新 | P0 |
| 分类 | 一级/二级分类树、分类跳商品列表 | P0 |
| 搜索 | 历史搜索（本地持久化）、热门搜索、结果排序（综合/销量/价格升降序） | P0（排序 P1） |
| 商品详情 | 图集、SKU 规格选择（颜色/尺码）、价格库存联动、富文本详情、收藏、分享、加购/立即购买 | P0 |
| 购物车 | 商品列表、数量步进、单选/全选、失效商品、价格合计、结算 | P0 |
| 订单 | 确认订单（地址/优惠券/备注）、下单、模拟支付、订单列表（状态 Tab）、订单详情、取消、确认收货、退款申请 | P0 |
| 地址管理 | 增删改查、默认地址、剪贴板智能填充（Scenario Fusion Kit） | P0（智能填充 P2） |
| 个人中心 | 头像/昵称编辑（相机/相册权限）、我的订单入口、收藏夹、浏览足迹、优惠券、设置（深色模式/清缓存/退出） | P0 |
| 评价 | 订单评价（评分+文字+图片）、商品详情页展示评价列表 | P1 |
| 消息 | 站内消息列表、本地通知（下单成功提醒） | P1 |
| 鸿蒙特色 | 服务卡片（FormKit）、跨设备流转/分布式数据、一多断点适配、深浅色 | P2（一多适配 P1） |

### 4.3 核心流程（验收主线）

登录 → 首页浏览 → 搜索/分类找商品 → 商品详情选 SKU → 加入购物车 → 购物车结算 → 确认订单（选地址）→ 模拟支付 → 订单列表查看 → 确认收货 → 发表评价

### 4.4 订单状态机

待付款 →（支付）→ 待发货 →（后台发货）→ 待收货 →（确认收货）→ 已完成
待付款 →（取消/超时）→ 已取消；已付款 →（申请退款）→ 退款中 → 已退款

## 6. 技术方案

### 6.1 总体架构

- 客户端：HarmonyOS App（ArkTS + ArkUI 声明式 UI + Stage 模型）
- 通信：RESTful + JSON over HTTP（统一响应体 `{code, message, data}`）
- 服务端：Spring Boot 3.5 + Spring Security(JWT) + MyBatis-Plus + MySQL 8 + Redis
- 管理端（选做）：轻量 Web（Vue3）
- 加分项：服务卡片 / 跨设备流转（需真机 + 分布式签名）

### 6.2 客户端技术选型

| 领域 | 选型 | 说明 |
|---|---|---|
| 语言/UI | ArkTS + ArkUI 声明式 | 官方主推，FA 模型已废弃 |
| 应用模型 | Stage（UIAbility 生命周期） | 官方案例同款 |
| 路由 | Navigation（支持一多双栏） | @ohos.router 备选 |
| 状态管理 | V1（@State/@Prop/@Link/@Observed + AppStorage/LocalStorage）+ V2（@ObservedV2/@ObjectLink/@Provider/@Consumer + AppStorageV2） | 购物车等复杂对象联动用 V2（有官方 Codelab 范本） |
| 网络 | @ohos.net.http 自封装（拦截器/泛型解析/统一错误码/loading） | NEXT 生态三方库少，自封装最稳；IM 项目可直接迁移 |
| 本地存储 | preferences（token/搜索历史/主题）+ relational store（足迹/购物车兜底） | @kit.ArkData |
| 图片 | Image 组件 + 占位/失败态 | 网络图片注意权限声明 |
| 交互组件 | Swiper、WaterFlow、Tabs、自定义 Dialog/Popup、属性动画 | |
| 支付 | 模拟支付（收银台页 + 后端状态流转） | 真实支付需企业资质 |
| 通知 | NotificationKit 本地通知 | 免推送资质 |
| 分布式（P2） | FormKit 服务卡片；分布式数据/跨设备流转 | 需真机 + 分布式签名，无真机则写成设计说明 |

### 6.3 服务端技术选型

| 领域 | 选型 |
|---|---|
| 框架 | Spring Boot 3.5（JDK 17+）+ Spring Security + JWT |
| 持久层 | MyBatis-Plus（逻辑删除/自动填充/分页） |
| 数据库 | MySQL 8 |
| 缓存 | Redis（商品详情/分类树/验证码/首页聚合） |
| 接口文档 | SpringDoc/OpenAPI（/doc.html） |
| 规范 | 统一响应体 + 全局异常处理 + 参数校验 |

## 10. 风险与对策

| 风险 | 对策 |
|---|---|
| DevEco/SDK 版本装不到官网要求 | 退而求其次：保证 API 12+，compileSdk ≥ 真机系统 API；论文中说明版本策略 |
| 模拟器白屏/无法联网 | 检查 module.json5 声明 ohos.permission.INTERNET；后端地址用局域网 IP，不用 localhost |
| ohpm 依赖拉取慢 | 配置国内镜像源；优先用系统能力，少引三方库 |
| 分布式能力做不了 | 需真机 + 分布式签名；没有就降级为"设计说明"写入论文 |
| 真实支付/推送不可用 | 一律模拟实现，论文中说明取舍原因 |
| 时间不足 | P0 优先，P2 果断砍；核心流程跑通就是胜利 |
| 查重不过 | 代码自己写，论文自己组织语言，不抄开源 README |
